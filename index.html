LONGEST COMMON SUBSEQUENCE

LCS：找出共同的順序

從最長共同子序列的概念開始， 逐格建立 DP 表，再沿著路徑找回答案。 最後把比較單位從字元換成單字，解開 UVa 531。

01 / CONCEPT

LCS 是什麼？

LCS 全名是 Longest Common Subsequence， 中文為「最長共同子序列」。

子序列：可以跳過，不能改變順序

在 ABCBDAB 中， 挑選第 2、3、4、6 個字元，可以得到 BCBA。

A B C B D A B

若一個序列能按照相同順序出現在 A、B 中， 它就是共同子序列。 其中長度最長的，就是 LCS。

Subsequence 不等於 Substring

子序列不要求連續； 子字串必須連續。

例如 ABC 與 AC： LCS 為 AC，長度 2； 最長共同子字串則只有 A 或 C，長度 1。

LCS 也不是集合交集。AB 與 BA 都有 A、B， 但順序不同，所以 LCS 長度只有 1。

答案可能不只一個。 ABCBDAB 與 BDCABA 的 LCS 長度為 4； BCBA、BDAB、BCAB 都是有效答案。
02 / DYNAMIC PROGRAMMING

用動態規劃解 LCS

先定義狀態

dp[i][j]： A 的前 i 個元素， 與 B 的前 j 個元素的 LCS 長度。

i、j 代表「個數」， 對應最後元素的陣列索引為 A[i-1]、B[j-1]。

表格需要多一列、一欄， 表示空序列，因此大小為 (n+1) × (m+1)。 

邊界：
dp[0][j] = 0
dp[i][0] = 0

若 A[i-1] == B[j-1]：
dp[i][j] = dp[i-1][j-1] + 1

否則：
dp[i][j] = max(
    dp[i-1][j],
    dp[i][j-1]
)

① 相同：左上角 + 1

可以把這對相同元素接在較短前綴的最佳答案後面， 所以長度增加 1。

② 不同：上方與左方取大

分別考慮不使用 A 的最後元素， 或不使用 B 的最後元素， 保留較長的結果。

③ 由上到下、由左到右

每格只需要左上、上、左的結果。 依此順序填表，相依狀態都會先完成。

為什麼這樣能保證得到最長答案？

若最後元素相同，可以取一個包含這對末尾元素的最優解； 移除最後配對後，剩下的是較短前綴的最優解。

若最後元素不同，任何共同子序列至少不使用其中一個末尾元素。 因此答案一定落在「去掉 A 末尾」或「去掉 B 末尾」 這兩類問題之中，取兩者最佳長度的最大值即可。

這是最優子結構； 遞迴分支會重複遇到相同的前綴， 則是重疊子問題。

03 / ANIMATION

LCS 填表與回溯動畫

請按「下一步」觀察每格計算。 填表完成後，動畫會從右下角回溯，最後反轉答案。

回溯規則： 元素相同，選入答案並走左上； 不同則走向上方或左方較大的 DP 值。 若相同大，可任選一邊。 因為答案由末尾往前收集，最後需要 reverse。
04 / COMPLEXITY

時間與空間複雜度

為什麼是 O(nm)？

A 有 n 個元素，B 有 m 個元素； 非邊界狀態共有 n × m 格。 字元比較與取最大值可視為常數時間， 所以填表時間為 Θ(nm)。

回溯每一步至少讓 i 或 j 減 1， 最多走 n+m 步，因此為 O(n+m)。

完整 DP 表占 Θ((n+1)(m+1)) 空間， 通常簡寫為 O(nm)。

UVa 531 比較單字。 若最大單字長度為 L，直接比較字串的嚴格上界為 O(nmL)。 題目限制 L < 30，通常視為常數。

調整長度，看計算量

2,400 非邊界狀態
9.8 KiB / 32-bit 整數表

估計空間 = (n+1)(m+1) × 4 bytes。 不含容器開銷，也不代表 Python 整數的實際占用。

方法 時間 額外空間 特性
直接遞迴 O(2n+m) 上界 O(n+m) 堆疊 重複計算很多子問題
記憶化遞迴 O(nm) O(nm) 表與 O(n+m) 堆疊 每個狀態最多算一次
二維 DP＋回溯 O(nm+n+m) O(nm+n+m) 能取得實際序列
滾動陣列 O(nm) O(min(n,m)) 只求長度時適用
Hirschberg O(nm) O(min(n,m)) 工作空間* 低記憶體還原序列

* Hirschberg 的工作空間慣例不計輸入、輸出； 遞迴堆疊另有 O(log(max(n,m))) 開銷。

05 / UVA 531

Compromise：共同的單字序列

題目要做什麼？

兩位政治人物各提出一份提案。 找出兩份文字中，順序相同、長度最長的共同單字序列。

這就是 LCS。 差別只是比較單位從「字元」變成「單字」。

  1. 讀入第一份文字，直到 #。
  2. 讀入第二份文字，直到 #。
  3. 以完整單字建立 LCS 長度表。
  4. 回溯取得單字，反轉後輸出。
  5. 重複處理，直到 EOF。

輸入與輸出規則

第一份提案，可跨很多行
#
第二份提案，可跨很多行
#
下一組測資……
EOF

每份文字少於 100 個單字； 每個單字少於 30 字元； 單字為小寫、無標點。 官方保證至少有一個共同單字。

每組輸出一行，單字間一個空白。 多個最優答案時，任一個皆可。

容易搞錯： 每一份提案都需要一個 #， 因此一組測資共有兩個 #。 換行不代表提案結束。

                目前這列只依賴上一列，
                以及本列左邊的結果。
                所以只求長度時，可以保留兩列，
                將空間降為 O(min(n,m))。
            


            

                但 UVa 531 要輸出單字。
                舊資料被覆蓋後，不能直接沿完整表格回溯。
                想兼顧低記憶體與實際序列，可進一步學 Hirschberg。
            

        


        

            
延伸二：最少插入與刪除


            

                若 LCS 長度為 ℓ，
                將 A 變成 B 的最少插入＋刪除次數為：
            


            
n + m − 2ℓ


            

                保留共同的 ℓ 個元素；
                刪除 A 其餘部分，再插入 B 缺少的部分。
            


            

                此公式只適用插入與刪除。
                若替換也算一次操作，就不能直接套用。
            

        

    


    

        常見錯誤：直接貪心配第一個相同元素
        

            A = ABC、B = BCA。
            若先把 A 的第一個 A 配上 B 最後的 A，
            後面無法再選，只得到長度 1。
            但真正的 LCS 是 BC，長度 2。
        

    


    

        常見錯誤：元素不同就把 DP 格子設為 0
        

            這是最長共同子字串的一種轉移方式，因為它要求連續。
            LCS 可以跳過，所以不同時應繼承上方或左方的最大值。
        

    


    

        常見錯誤：只輸出 dp[n][m]
        

            dp[n][m] 是長度，
            UVa 531 要的是實際的單字序列。
            必須回溯，收集單字，再反轉輸出。
        

    


    

        常見錯誤：認為答案一定與 Sample Output 完全相同
        

            當上方與左方的值相同，選不同方向可能得到不同答案。
            只要是合法的最長共同單字序列，
            UVa 531 就允許。
            本頁預設平手優先向上。
